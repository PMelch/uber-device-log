Über Device Log — Changelog
===================
User-visible changes are recorded here in English, newest version first.
Unreleased contains only changes after the latest published version.
Historical entries were reconstructed from release-tag diffs and the npm
publication history. Dates are npm publication dates in Europe/Vienna.
Version 0.4.0 has no Git tag; its source baseline is the npm gitHead e26c0c1.

Unreleased
----------

Fixed
- Keep pinned log details open during live capture and automatic scrolling on
  iOS and Android, even after the original row leaves the virtualized view.

Added
- Filter native iOS logs by observed process name across PID changes, with an
  optional exact PID. The Android-style searchable picker lists names from
  retained logs, not running processes; original syslog text stays unchanged.
  Native iOS process controls open immediately in source filters, without an
  unsupported severity section; Android and WebView severity controls remain.
- Show a localized loading label during web startup and an animated spinner
  while the terminal interface initializes.
- Search running Android processes by package/process name and apply a selected PID
  directly to the source filter, with refresh and support for secondary processes
  and system process names containing spaces. The compact search dialog keeps
  search and actions visible while large process lists scroll independently.

Changed
- Color recognized native iOS log headers with coordinated light/dark timestamp,
  device, process, subsystem, PID and severity ink; preserve original text,
  existing diagnostic rendering and unsupported formats without changing capture.
- Make clearing the log viewer directly available through a compact trash icon
  in the toolbar, including on mobile screens.
- Refine source filter menus with separate search controls, grouped PID lookup,
  aligned severity choices and a compact reset footer with a reset icon.
- Show the shorter npx and bunx TUI commands without an extra argument separator
  in the website, README and CLI help. Both forms remain supported.

0.11.1 - 2026-11-04
-------------------

Fixed
- Include the terminal interface and Flow worker in the npm package so `udl --tui`
  runs without a checkout or local build. Bun 1.3.14+ remains required (1.4+ on
  Windows arm64); runtime dependencies are installed for the user's platform.
- Accept the forwarded `--` separator for `npx uber-device-log@latest -- --tui`
  and `bunx uber-device-log@latest -- --tui`.
- Use CLI commands in README and website usage examples, explain the packaged TUI
  and its Bun requirement in all seven languages, and update terminal upgrade
  guidance for package installations. Remove the outdated README publication notice.

0.11.0 - 2026-11-04
-------------------

Added
- Inspect terminal logs as structured diagnostic details, original text or JSON,
  using the same parsers and explanations as the web viewer.
- Show available updates at terminal startup with source-update instructions,
  without blocking capture or automatically installing updates.
- Manage global and project Flow sources in the TUI without a web server: search,
  inspect conflicts, enable bundles and install from URLs or a local file picker.
- Add a terminal Semantic Flows screen with searchable live summaries, status and
  completeness indicators, an event timeline, masked payloads and explicit raw-log
  inspection. Analyze selected sources in an isolated worker using the same global
  and project blueprints as the web viewer, with capture-gap and timeout handling.
- Add an optional terminal log viewer via `udl --tui` with direct device capture
  without a web server, combined native/WebView sources, mouse and Tab navigation,
  literal/fuzzy search, paused inspection and JSON export. Project options remain usable;
  a host-specific TUI build is required. The synthetic demo remains available.
  Collapse the Sources panel with F6 or expand the log stream with F11; leaving
  fullscreen restores the previous panel state without interrupting capture.
  Keep the shared search field visible in fullscreen to filter all active sources.
  Click the controls in the Sources and Log stream borders to change their layout.
  Adapt terminal colors automatically or choose light, dark or monochrome display;
  severity and source accents preserve readable contrast, including selected rows.
  Blink the pause button while the view is frozen, keeping its label readable.
- Add terminal Settings for language, colors, message order and retained record
  capacity, using compact current-value fields with keyboard and mouse popovers
  and a clickable [X] close control in the Settings frame.
  Language and color controls live in Settings, keeping the main toolbar compact.
  Manual source refresh is available at the end of the Sources panel.
  Changes apply immediately for the current session while capture continues.
- Add a terminal WebView JavaScript console with explicit target/context selection,
  command history and expandable result properties while log capture continues.

Changed
- Hide the Interpretation section in web and terminal log details when no specific
  explanation matches the entry.
- Present the web and terminal viewers in a manual website screenshot carousel,
  with terminal setup guidance and a real TUI capture in the README.
- Size each terminal Settings field and the Close button to its own content
  instead of stretching them across the screen.
- Keep Settings and Quit together at the right edge while other toolbar actions wrap.
- Hide the source column in web and terminal log lists when only one source is
  selected, leaving more room for messages; restore it for combined sources.

Fixed
- Return the terminal viewer to live mode when a source is enabled again, instead
  of keeping an empty frozen view while new events are captured in the background.
- Refresh terminal device and WebView choices automatically, remove closed targets
  and stop only their capture while keeping remaining sources and captured logs.
- Start the terminal interface directly from source with `npm run dev -- --tui`,
  including project options, without launching the web server or requiring a build.
- Discover Android WebViews reliably in web and terminal interfaces when the ADB tunnel
  opens asynchronously; support both source and bundled Bun adapter imports.

0.10.0 - 2026-11-03
-------------------

Added
- Add Semantic Flows with YAML blueprints for standalone events and correlated
  multistep operations, including branches, expected errors and missing-start
  detection. Inspect timelines and original evidence beside raw logs, and edit
  and validate definitions in the viewer. A terminal start can recognize a single
  event without an operation ID in the log.
- Default project Semantic Flow blueprints to .udl/flows, with a configurable
  project-relative path in .udl/config.yaml.
  Automatically migrate legacy .flowsrc settings and the default .flows directory
  without overwriting existing configuration or conflicting destination files.
- Load global Semantic Flows from ~/.udl alongside project definitions. Install
  validated .blueprint ZIP bundles from local files or URLs through the interface
  or CLI, without a temporary file server. Inspect
  their names, descriptions and specification versions, and enable or disable them
  independently per project or globally without a project. Report duplicate IDs
  with their origins and stop recognition for disabled bundles while retaining logs.
- Continue a normal expected step without an identifier only when exactly one
  eligible candidate is waiting and no primary or alias extractor is declared.
  Multiple candidates remain ambiguous; repeated steps and error rules still
  require explicit correlation.
- Recognize alternative Semantic Flow entry points that converge on shared steps.
  Share per-instance variables across entries and branches, and mark unchosen
  entry paths as alternatives in the overview and Timeline.
- Define dynamic Flow labels with extracted payloads and semantic text colors,
  and show explicitly marked result fields. Detailed and Condensed views retain
  the same summaries while concealing sensitive values. Active flows show progress
  with a reduced-motion-aware spinner. Include a bank-transfer example covering
  success, rejection, cancellation and review.
- Add a Minimal flow overview that shows only each current main label, alongside
  the existing Condensed and Detailed views. Remember the selected view. Open
  a Minimal entry's Timeline by clicking it or using Enter or Space.
- Highlight flows by blueprint priority (1–5, default 3) with separate light and
  dark palettes, independent of outcome. Edit priority in the blueprint draft
  selector; include priority guidance in the portable authoring skill.
- Allow explicitly correlated, repeatable flow steps to update progress labels and
  result fields until the flow advances or ends. Use the latest accepted values
  in downstream references. Include a loading-progress example and authoring skill guidance.
- Provide opt-in Android diagnostic Blueprint bundles for frame scheduling,
  slow rendering, startup, ART garbage collection, allocation failures,
  low-memory kills, ANRs and fatal reports using existing Logcat signals.
  Include reproducible archives, source evidence and installation guidance.
- Provide a portable Semantic Flows authoring skill for project Blueprints and
  new or existing bundles, with the format reference, extraction and validation
  guidance, examples, safe bundle packaging and cross-agent installation steps.
- Introduce Semantic Flows on the website in all seven interface languages, with
  guided README tutorials for single events, correlated multipart operations and
  branching routes, including complete Blueprints and reproducible example logs.
  Link directly to the Android Blueprint collection on GitHub for downloads and setup.
- Refresh README and website screenshots, and highlight the built-in software
  setup guides in the README and all seven website languages.

Changed
- License the project under GNU GPL version 3 only (GPL-3.0-only) instead of
  Apache-2.0. Third-party platform icons retain their separate CC0 license.
- Provide reproducible Flow formatting, lint and browser checks for contributors,
  and run product tests/builds on pull requests including the minimum Node version.
- Manage Blueprint sources in a toolbar-opened dialog with a searchable global/project
  list and a selected-source inspector for descriptions, metadata, definitions and
  diagnostics. Keep bundle installation collapsed, retain drafts when closing, and
  support keyboard focus, Escape dismissal and smaller screens.
- Validate required flow references against every incoming route and required
  extractions, including existing branch joins. Use explicit optional references
  for values that may be absent; missing comparisons never match.
- Show the blueprint name with its ID in parentheses above detailed flow labels;
  hide that line in condensed summaries. Omit the generated instance ID from
  the main label row.
- Inspect JavaScript result objects on demand, load further properties in pages,
  and explore nested objects without evaluating the expression again or invoking getters.
- Show JavaScript console contexts in frame hierarchy order, with nested frames
  indented beneath their parents and the main page first.
- Show observed steps and immediately expected alternatives on Flow cards, with
  later steps behind an ellipsis. Draw forks, detours and joins as rounded lanes
  in the overview, Timeline and Blueprint graph; dim unchosen routes and keep
  the first card lane straight, including forks with more than two alternatives.

Fixed
- Resolve website Blueprint and tutorial links against the build branch, avoiding
  missing pages before merge while automatically using main after merge.
- Keep out-of-order events with their original operation and Blueprint revision,
  including overlapping flows and definition changes. Running flows can finish
  without starting new flows retroactively from buffered records.
- Enforce deadlines independently of timer ticks, and prevent stale progress or
  rejected branch evidence from changing later flow state. Bound deep JSON
  analysis and require finite, safely representable timeouts.
- Preserve Flow ambiguity and missing-start evidence across capture gaps and
  truncated records. Close timed-out recognition after its first late terminal
  result, allowing a fresh operation without reusing old buffered evidence.
- Keep Semantic Flow analysis running when a captured JSON error code cannot be
  converted to text. Use the rule's unknown outcome, preserve sensitive original
  evidence, and distinguish missing codes from the literal string "undefined".
- Preserve keyboard focus in the JavaScript console when a connection finishes,
  so Escape dismisses a feature tooltip without closing the console.
- Keep semantic-flow connectors at their graph dimensions inside the app, so
  global icon sizing no longer offsets or clips branches and detail diagrams.
- Keep long graph labels within their hit areas and render dense valid Flow
  graphs without stalls.

Security
- Conceal sensitive Flow error codes in decorations and search.

0.8.0 - 2026-10-19
------------------

Security
- Pin patched shell-quote and source-map-js versions in the development checkout.
  Published installations still depend on Appium's upstream shell-quote pin;
  report this known finding during package verification. Install dependencies on
  the target host without bundling build-host native binaries.

Added
- Show a compact summary of active search, tag, PID and severity filters in each
  source row without increasing its height; retain full values in accessible labels
  and tooltips when space is limited. Explicitly show all levels when severity
  filtering is unrestricted.
- Show the number of log records received while the view is paused, including
  records that have since left the live buffer.
- Confirm successful copying directly on the Copy button.

Changed
- Refresh README and website screenshots for the current interface and
  move detailed interaction guidance into a dedicated user guide. Keep the README
  focused on setup, capabilities and capture limits.
- Combine the stream title and capture status with the action toolbar, freeing
  vertical space for logs while retaining a stable toolbar height across states.
  Keep capture status beside the title and group Save with Pause.
- Present stream sources as compact selection chips with clear selected states,
  keyboard focus, touch targets and restrained transitions.
- Give source filter rows a contrasting surface, stronger outline and clearer
  source names in both light and dark themes without changing their layout.
- Use compact WebView titles and domains with clear selection marks; show full
  URLs and target identifiers in accessible details popovers. Disambiguate
  matching pages with paths and identifiers only when needed.
- Show the Select button only for touch-style primary pointers. Desktop users
  select entries directly through rows or checkboxes; keyboard selection remains
  available. Finishing selection restores focus to a visible control.
- Keep the log viewport stationary when entering selection mode, opening filters
  or additional actions, and pausing the view. Use compact source filter rows,
  overlay panels and a fixed-height toolbar on desktop and mobile.
- Group additional selection/export actions and the export-format selector in
  More actions, using compact grouped menu rows and collapsible help instead
  of stacked full-width buttons. Open the manual-copy fallback as a dialog.
- Replace the continuous pause pulse with restrained transitions that honor
  reduced-motion preferences. Localize new controls in all seven UI languages.
- Update the public website to emphasize combined native and WebView logging
  for hybrid apps, and use uber-device-log.app as the website domain.
- Expand contributor, architecture, API/export, testing and release documentation.

Fixed
- Keep log details open when activating an existing hover or keyboard-focus
  preview; the first activation pins it instead of immediately dismissing it.
- Copy and save logs oldest first regardless of the selected display order.
- Discover Android WebViews even when the device's socket table exceeds 1 MiB.
  Filter socket records incrementally with bounded memory instead of rejecting
  the complete table. Preserve timeouts, deduplication and the 32-socket limit.

0.4.0 - 2026-09-30
------------------

Added
- Initial npm release with Android Logcat and iOS syslog capture in a local
  browser viewer, device discovery, connection status and manual reconnection.
- Launch through npx, bunx or the globally installed udl and uber-device-log
  commands, with port, help and version options. Require Node.js 22.12 or newer.
- Search log messages and metadata, filter Android severity levels, switch
  message order, follow incoming logs, and clear the viewer.
- Pause the view while capture continues, select whole entries with mouse,
  keyboard or touch controls, and copy or save selected or filtered logs as
  plain text or structured JSON.
- Format recognized Java, native Android and iOS crash diagnostics and expose
  message details, original text and JSON in a details popover.
- Offer English, Spanish, German, French, Italian and Simplified Chinese UI text
  while preserving original log content and technical data.
- Remember language, appearance, message order, buffer capacity and the last
  selected device. Restore capture on reload when that device is available.
- Provide responsive layouts and System, Light and Dark appearance options,
  with a bounded log buffer configurable up to 100,000 entries.
